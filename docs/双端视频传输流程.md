# 实时视频系统：客户端与服务端如何完成一次观看

本文沿双端交接说明一次观看如何建立、传输、恢复、切换与退出。模块职责见 [服务端概览](服务端模块说明.md) 和 [客户端概览](../../sclient/docs/客户端模块说明.md)，具体协议和参数按文末入口查阅。

时序图表达主要因果关系，参与者代表职责边界，不一一对应线程；图中未展开的并发、排队与超时仍可能影响实际耗时。

## 1. 双端通信约定

| 通道 | 方向与用途 |
|---|---|
| TCP 控制 | 客户端发 START、STATUS、STOP、KEYFRAME，服务端返回实际状态 |
| UDP 下行 | 服务端发视频数据片、FEC 校验、重传与保活确认 |
| UDP 上行 | 客户端发注册、接收质量报告和 NACK |

控制端口用于连接管理服务；START 返回的媒体端口是服务端 UDP 端口；客户端本地 UDP 源端口才是其接收位置的一部分。服务端由上行报文源地址学习端点，也可通过 STATUS 的 media_port 辅助更新。

正式客户端 START 请求显式 session，使用 port=0 分配服务端媒体端口。设备留空沿用服务端策略；`quality` 表达画质，`profile` 表达网络策略，服务端配置决定 `media_profile`。

TCP 连接、观看会话、UDP 端点、采集组和编码子流各有生命周期。控制断开不等于媒体立即停止，一个观众退出也不等于关闭所有共享资源。

## 2. 建立观看并注册接收地址

```mermaid
sequenceDiagram
    actor U as 观看者
    participant C as 客户端应用与控制
    participant S as 服务端控制与应用
    participant P as 服务端采集与编码
    participant T as 服务端媒体传输
    participant R as 客户端媒体接收
    U->>C: 提交服务器、画质和可选设备
    C->>S: 连接 TCP，START 显式 session
    S->>S: 检查请求、容量和设备兼容性
    S->>P: 创建或引用所需采集与编码
    P-->>S: 就绪或失败
    alt 资源与传输准备成功
        S->>T: 创建或复用传输，配置可选密钥
        S-->>C: Running 与实际端口、codec、设备、色彩和密钥
        C->>C: 校验响应，采用本轮实际配置
        C->>R: 初始化媒体接收与可选 AES-GCM
        R->>T: UDP 注册与完整接收报告
        T->>T: 认证校验，登记源 IP 与端口
        T-->>R: 保活确认
    else 校验或资源失败
        S->>S: 回收本轮取得的资源引用
        S-->>C: ERR 与失败原因
        C-->>U: 展示问题，等待后续操作
    end
```

START 成功表示观看关系建立；UDP 注册使服务端知道视频应发往哪里；真正显示还需下一节的完整媒体链路。注册前的编码帧不会为该观众无限积压。

加密 START 每次建立新密钥与传输上下文，客户端先初始化加密再发送上行注册；响应密钥非法或与请求不一致时连接失败。同参数明文 START 可幂等复用，不能据此推断所有重复 START 都保留原端口和密钥。

密钥通过控制响应交付，媒体认证不等于控制通道加密或身份认证。加密外层和字段布局见 [两端媒体加密模块](#10-深入阅读)。

## 3. 一帧视频从摄像头到屏幕

```mermaid
sequenceDiagram
    participant CAP as 服务端采集
    participant E as 服务端编码子流
    participant A as 服务端应用分发
    participant T as 服务端传输
    participant R as 客户端接收
    participant D as 客户端解码
    participant G as 客户端显示
    participant V as 客户端录像
    CAP->>E: 共享原始帧引用与采集信息
    E->>E: 格式适配、缩放与压缩
    E->>A: 完整压缩帧及设备、档位归属
    A->>T: 匹配活动订阅，投递有界发送邮箱
    T->>T: 分片，按策略加入 FEC、pacing 与加密
    T-->>R: UDP 数据报，可能丢失、乱序或重复
    R->>R: 认证、字段校验、重组、恢复与有限排序
    opt 录像已开启
        R->>V: 在解码队列丢帧前复制完整压缩帧
        V->>V: 等待参数与关键帧后封装 MP4
    end
    R->>D: 完整压缩帧
    D->>D: 检查参考连续性，解码产图
    D->>G: 带资源所有权的最新图像
    G->>G: 上传或导入、颜色转换与实际绘制
```

兼容的同设备观众共享采集，同档位共享编码；应用按订阅选择发送目标。加密、自动画质或自动网络策略会话独享传输，符合条件的固定画质明文会话可共享传输。

各阶段通过有界队列交接。发送跟不上时不无限堆积旧视频，客户端显示也只消费最新图像；压缩帧被丢弃时可能需要恢复参考链。

服务端发送、客户端完整帧、解码产图、渲染提交和实际绘制是不同成功点。跨主机时间也不能直接裸相减，端到端估算的测量边界见两端概览。

## 4. 持续反馈与会话续租

```mermaid
sequenceDiagram
    participant R as 客户端媒体接收
    participant C as 客户端控制
    participant T as 服务端媒体传输
    participant S as 服务端会话管理
    participant P as 服务端编码策略
    par UDP 媒体报告
        loop 按媒体报告周期
            R->>T: KeepAlive、接收质量与逐包反馈
            T-->>R: 回显报告时间，供 RTT 估算
            T->>T: 评估网络保护、FEC 与发送预算
            T->>S: 活动会话的丢包、RTT 与带宽反馈
            S->>P: 汇总活动子流反馈，评估 ABR
            S->>S: auto 画质另行评估主子切换
        end
    and TCP 观看续租
        loop 按控制保活周期
            C->>R: 读取当前本地 UDP 端口
            C->>S: STATUS session 与 media_port
            S->>S: 刷新媒体会话租约
            S->>T: 按控制来源 IP 辅助续活或更新端点
            S-->>C: 本会话实际状态
        end
    end
```

| 决策 | 作用范围 |
|---|---|
| 网络 profile | 分片和发送保护，自动模式在帧边界生效 |
| ABR | 共享编码子流的目标码率与降级意图，联动 pacing |
| 自动画质 | 某个会话当前选择主流还是子流 |
| 客户端本地缓冲 | 本机有限排序、等待和跳帧 |

这些决策相互配合但各有条件。关闭 ABR 不关闭自动画质；profile=auto 与本地缓冲 strategy=auto 也不是同一个选项。

UDP 报告不能替代 START/STATUS 对媒体会话的续租，STATUS 也不能替代包级质量反馈。码率目标与实际编码输出还要分别观察，后端限制见 [编码说明](../modules/encoding/README.md)。

## 5. 从补片到关键帧恢复

```mermaid
sequenceDiagram
    participant T as 服务端媒体传输
    participant R as 客户端重组与恢复
    participant D as 客户端解码与播放
    participant C as 双端控制链
    participant E as 服务端活动编码子流
    T-->>R: 数据片与可选 FEC，部分数据片缺失
    alt 组内仅缺一片且校验可用
        R->>R: 校验布局，XOR 恢复缺片
    else FEC 未补齐且重传预计来得及
        R->>T: NACK 指定帧号与缺片号
        alt 缓存有效且有立即发送额度
            T-->>R: 使用原分片布局补发
        else 缓存过期、无额度或背压
            T->>T: 不满足本次补发
        end
    end
    alt 在等待预算内收齐
        R->>D: 交付完整压缩帧
    else 超时或预算耗尽
        R->>R: 清理或跳过缺帧
        R->>D: 后续帧暴露序号断档
        D->>D: flush 并等待随机接入关键帧
        opt 当前帧不可用于重建且冷却允许
            D->>C: 非阻塞投递并合并 KEYFRAME 请求
            C->>E: 定位本会话活动子流，要求关键帧
            C-->>D: 请求接受结果
        end
        E-->>D: 后续关键帧经正常媒体路径到达
        D->>D: 成功解码产图后恢复，继续显示交接
    end
```

- FEC 每组一份 XOR 只能修复该组一个缺口，需要校验和其余数据齐全、布局一致。
- NACK 受乱序等待、RTT、期限、次数、令牌和熔断限制；服务器还要检查缓存与发送额度。
- 补片修复帧内容，关键帧修复解码参考。若断档后的当前帧已可重建参考，就不必再请求。
- KEYFRAME 成功响应仅表示接受请求；关键帧自身仍可能丢失，恢复要看实际产图和显示进展。

服务端发送队列丢弃压缩帧时，也可在本地触发关键帧恢复信号。同一编码子流的其他观众可能收到该关键帧，不能把共享编码理解为完全隔离。

## 6. 手动切换与自动切档

### 6.1 用户提交新的观看请求

```mermaid
sequenceDiagram
    actor U as 用户
    participant A as 客户端应用与播放
    participant C as 客户端控制
    participant S as 服务端会话管理
    participant P as 服务端共享资源
    U->>A: 提交新的地址、端口或画质
    A->>A: 比较有效字段，结束当前播放与录像
    A->>C: 尽力停止旧显式 session
    C->>S: STOP 旧会话
    S->>P: 成功时归还该会话引用
    A->>C: 关闭旧控制上下文
    A->>A: flush 解码器，应用新请求并生成新 session
    C->>S: 重新连接与 START
    S-->>A: 本轮实际端口、codec、设备与密钥
    A->>A: 重新注册媒体，等待关键帧并播放
```

有效切换比较主机、端口、传输、profile 和 quality，相同请求忽略。当前 device 未参与比较，仅修改设备不保证触发在线重连。

旧 STOP 未确认时，下一轮仍使用新 session，不依赖同名替换；旧资源可能暂存，由租约兜底回收。不会用无 session 的全局 STOP 清理。

### 6.2 auto 在原会话内切换主子流

```mermaid
sequenceDiagram
    participant R as 客户端反馈与播放
    participant T as 服务端传输
    participant A as 服务端应用
    participant P as 共享采集与编码
    R->>T: 有效接收质量报告
    T->>A: 当前会话质量反馈
    A->>A: 连续报告满足升降档条件
    A->>P: 创建或引用目标编码子流
    alt 目标准备失败
        A->>A: 保留当前活动流
    else 目标就绪
        A->>A: 更新活动订阅，等待目标关键帧
        A->>P: 归还旧流引用，无人使用则释放
        A->>P: 请求目标流关键帧
        P-->>A: 目标流压缩帧
        A->>T: 按新活动订阅投递，目标关键帧前不放行
        T-->>R: 原会话与传输继续发送，目标流从关键帧开始
        R->>R: 解码新尺寸，成功后保留参考链继续播放
        R->>R: 录像参数变化时分段续录
    end
```

自动画质初始只持有主流，稳定档位下只保留当前一路；没有配对子流时按实际能力回落。无需客户端主动重连，但目标初始化、排队和关键帧到达仍可能产生等待。

自动网络 profile 切换是另一种调整：它改变分片与保护，在帧边界生效，不重建 socket、密钥或编码器。切换门槛见 [网络配置](../config/README.md#udp-丢包恢复差异)。

## 7. 断流、换端口与服务端重启

```mermaid
sequenceDiagram
    participant A as 客户端应用
    participant R as 客户端媒体与解码
    participant C as 客户端控制
    participant S as 服务端会话管理
    participant T as 服务端媒体传输
    alt 本地媒体接口明确断连
        A->>R: 重建 UDP socket
        R->>T: 用新源端口注册
        opt 上行注册未到达
            C->>S: STATUS 与当前 media_port
            S->>T: 按控制来源 IP 辅助更新端点
        end
    else 长期没有图像提交进展
        A->>A: 结束旧播放管线，停用后台播放调度
        A->>C: 必要时重连 TCP
        C->>S: STATUS 显式 session
        S-->>A: Idle 或现有会话实际状态
        alt 空闲或会话与策略兼容，且预算允许
            C->>S: START 重新建立或挂接
            S-->>A: 本轮实际端口、codec、设备、色彩和密钥
            A->>R: 校验并更新配置，flush 后重建媒体接收
            R->>T: 注册当前端点
            A->>A: 启用下一轮播放，等待可用关键帧
        else 不兼容或会话恢复预算耗尽
            A->>A: 展示问题，等待用户操作
        end
    end
```

- TCP 短时断开时，租约与端点仍有效可继续收 UDP；STATUS 续租不等于取得 STOP/KEYFRAME 归属，成功 START 才可转移连接归属。
- STATUS 辅助更新端点时，无同源条目可补登记，单条目可改写，同 IP 多端点有歧义时只续活，不抢改端口。
- 同密钥仅重挂媒体连接时保留上行计数器；新的加密 START 则采用新材料，不能复用旧密钥与端口假设。

当前会话恢复分支在播放调度停用期间立即调用 KEYFRAME，该请求被拒绝，下一轮不会补发；仍需等待可用关键帧或后续恢复触发。

媒体、控制和会话恢复各有预算。会话恢复失败可回面板，本地接收管线重连全失败若先返回错误，正式客户端也可能退出；不承诺固定恢复总耗时。

服务端重启后，内存中的会话、设备引用、编码器、端点、密钥和重传缓存都需重建。客户端可保留观看意图，必须重新查询、START 并采用实际响应，无法补回旧缓存已丢失的历史帧。

## 8. 暂停、截图与录像

| 操作 | 客户端行为 | 对服务端的影响 |
|---|---|---|
| 暂停显示 | 后台接收、解码和已开启录像继续；恢复后显示最新图像 | 不发 STOP，反馈与续租继续 |
| 截图 | 保存视频控件 framebuffer，含缩放与留边 | 无额外媒体请求 |
| 开始录像 | 压缩帧进入独立队列，等参数与关键帧后创建 MP4 | 允许时请求活动子流关键帧 |
| 录像参数变化 | 结束旧文件，等待新参数与关键帧后续录 | 正常提供新流，服务端不操作本地文件 |
| 停止录像 | 关闭新帧入口，排空队列并写文件尾 | 不停止观看会话 |

暂停时截图请求会延后到恢复后消费，不能保证立即保存暂停画面。录像保存原压缩视频、不含音频，与显示截图的尺寸和帧集合可能不同。

录像队列或写盘失败通常只结束录像，播放继续；手动观看切换会结束当前录像。录像写入计数不代表文件已收尾，强制退出也不能保证最后片段完整。

## 9. 退出与共享资源回收

```mermaid
sequenceDiagram
    actor U as 用户
    participant A as 客户端应用
    participant P as 客户端播放与录像
    participant C as 客户端控制
    participant S as 服务端会话管理
    participant T as 服务端传输
    participant E as 服务端共享采集与编码
    U->>A: 退出或关闭窗口
    A->>P: 停止新工作，关闭队列并唤醒等待
    P->>P: 关闭媒体，回收接收与解码线程
    P->>P: 等待录像排空与文件收尾
    A->>C: 停用后台播放任务，关闭控制上下文
    C->>S: 有限预算尽力 STOP 自己的显式 session
    alt STOP 被接受
        S->>S: 摘除目标会话与活动订阅
        S->>T: 归还传输引用
        S->>E: 归还编码与采集引用
        E->>E: 各资源按自身引用归零回收，其他观众继续
        S-->>C: STOP 结果
    else 请求失败或释放未确认
        C->>C: 结束有限释放尝试
    end
    C->>C: 结束控制连接与线程
    A->>A: 在图形上下文中释放 GL，再销毁窗口
    opt 目标会话仍存活且不再续租
        S->>S: 后续租约过期，复查后回收目标会话
    end
```

客户端发送 START 时就记录待释放 session，即使成功响应丢失，仍有明确的尽力 STOP 目标。清理失败不扩大成全局停止，本地退出不等待远端租约回收。

| 失效对象 | 到期后的主要动作 |
|---|---|
| TCP 控制连接 | 关闭连接、释放连接归属 |
| UDP 接收端点 | 移除失活接收地址 |
| 媒体会话租约 | 摘除观看关系并归还资源引用 |

三种有效期独立。租约候选在真正摘除前还会复查，避免回收刚被续租的观看；共享子流或采集组只在最后一个使用者离开后关闭。
